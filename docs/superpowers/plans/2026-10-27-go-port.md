# kandor Go Port Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Bash `kandor` script with a Go binary that behaves the same and reads a sectioned TOML configuration file.

**Architecture:** A thin `cmd/kandor` entry point calls `internal/app`, which parses the command line (`internal/cli`), loads and merges configuration (`internal/config`), prepares the agent's state (`internal/agent`, `internal/profile`), plans the `bwrap` argument list as a pure function (`internal/sandbox`), and runs it as a child process (`internal/run`). Every behaviour detail comes from the Bash script at commit `a71d84f` (`git show a71d84f:kandor`), referred to below as **the reference**; each task names the reference functions it ports.

**Tech Stack:** Go 1.27, `github.com/BurntSushi/toml` v1, `bwrap`, optional `git`; Bash smoke tests.

**Spec:** `docs/superpowers/specs/2026-10-27-go-port-design.md`

## Global Constraints

- Module path `github.com/dlawregiets/kandor`; `go 1.27` in `go.mod`.
- Only dependency outside the standard library: `github.com/BurntSushi/toml` (v1.x, latest).
- Linux only. `bwrap` is required at runtime; `git` is used when installed, skipped otherwise (as the reference does).
- Messages: `kandor: warning: <text>` and `kandor: error: <text>` on stderr; fatal errors exit 1. Keep the reference's wording for every existing warning and error unless a task says otherwise.
- `--version` prints `kandor 0.3.0`.
- Configuration path: `$KANDOR_CONFIG`, else `$XDG_CONFIG_HOME/kandor/config.toml`, else `~/.config/kandor/config.toml`. Old file: `$XDG_CONFIG_HOME/kandor/config`.
- Unknown configuration keys, unknown sections, wrong types and agents other than `opencode` are errors.
- Commit messages never include a `Co-Authored-By` line or any Claude attribution.
- Run `gofmt`/`go vet` clean before each commit.

## Review Focus

1. **Inherited file descriptors:** a descriptor kandor inherits from its parent (for example `exec 9</etc/hostname` in the calling shell) must not appear inside the sandbox. Go does not close inherited descriptors for children. Test: Task 12 step 1.
2. **Interrupted runs:** SIGTERM or SIGHUP to kandor while the sandbox runs must still stop the sandbox, remove the shared temporary profile and run the git audit. Test: Task 13 step 1.
3. **Exit status of a sandbox killed by a signal:** `kandor --shell -- -c 'kill -TERM $$'` must exit 143 (128 + signal), as Bash did. Test: Task 12 step 1.
4. **Paths with spaces or shell metacharacters:** a project directory like `my proj` must be mounted and `--dry-run` must print it quoted so it can be pasted into a shell. Test: Task 11 step 1 and Task 13 step 1.
5. **A configured path that does not exist:** `read_only = ["~/missing"]` must stop with `kandor: error: ro path does not exist: <path>` (reference wording), not a Go stack trace or a silently skipped mount. Test: Task 9 step 1.

### Task 3: Settings and layered merge

**Files:**
- Create: `internal/config/settings.go`, `internal/config/merge.go`, `internal/config/merge_test.go`

**Interfaces:**
- Consumes: `File`, `NewSessionMode` (Task 2); `paths.Expand` (Task 1).
- Produces:
  - `type MountSpec struct { Path string; Writable bool }`
  - `type EnvSpec struct { Name, Value string; HasValue bool }` (`HasValue` false means "copy from host", like `--env NAME`).
  - `type Overrides struct { ProjectDir string; Mounts []MountSpec; Env []EnvSpec; Network, AllowUserns, SSH, SSHAgent, GitCredentials, Netrc, Npmrc, MountGitConfig, ProtectGit, Isolated, Seed *bool; NewSession *NewSessionMode; Profile string }`: the command-line layer, filled in by Task 5.
  - `type Settings struct { ProjectDir string; Mounts []MountSpec; Env []EnvSpec; Network, AllowUserns bool; NewSession NewSessionMode; SSH, SSHAgent, GitCredentials, Netrc, Npmrc bool; MountGitConfig, ProtectGit bool; Isolated bool; Profile string; Seed bool; AgentBinary string }`
  - `func Merge(f *File, o Overrides, agent, home, cwd string, getenv func(string) string) (Settings, error)`

Rules (from the spec):
- Defaults: `Network`, `MountGitConfig`, `ProtectGit`, `Seed` true; `Profile` `"default"`; others false; `NewSession` `SessionAuto`; `ProjectDir` = `cwd`.
- Layer order: file top level, then `f.Agents[agent]`, then `o`. Scalars: later set value wins. `profile.name` in the file implies `Isolated = true` unless `profile.isolated` is also set in the file. `o.Profile`/`o.Isolated` are already ordered by the parser.
- Mounts: paths expanded with `paths.Expand`; emitted in layer order, `read_only` entries before `read_write` within a layer. A path present in both lists of the same layer → error `mounts: "<path>" is listed as both read_only and read_write`. Across layers no conflict: later entries win at mount time.
- Env: file `pass` (list order), file `set` (sorted by name), agent `pass`, agent `set` (sorted), then `o.Env`.
- `AgentBinary`: `getenv("KANDOR_BIN")` if non-empty, else `f.Agents[agent].Binary`, else `""`.
- `Profile` must match `^[A-Za-z0-9][A-Za-z0-9._-]*$`, else the reference's `invalid profile name` error.
